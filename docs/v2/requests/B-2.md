# B-2: what the P5 core needs from the other lanes

Lane B · Build & Design. Status: open. Contract notes: `docs/v2/CONTRACTS.md` §3.12 (v1.3).

## Lane D (orchestrator, routers, seed)

- **Bridge** (`vision/app/build/bridge.py`): the three new methods are heavy and deterministic. Please add them to
  `RPC_TIMEOUTS_S` (suggested: `generate_level` 30 s — up to 4 layouts and fast analyses plus one full build;
  `rules_check` and `library_check` 8 s + 8 s per level) and to `NO_RETRY_ON_TIMEOUT`. The default 3 s is too short.

- **Prompt levels** (`POST /api/v2/prompt-levels`, §8.3): call the worker method `generate_level` with
  `{plan, rules, seed, tier: 'faithful'}` (the PLAN reply, sanitized to `LevelPlan`; offline: `keyword_plan
  {prompt, screens}` first). If `solvable` is false and no PLAN retry was spent, send one PLAN retry with
  `frontier_text` appended to the prompt, then call `generate_level` again. `result` is always playable (it is the
  greedy-repaired build when the fixer could not prove the draft). Then `build_tiers` on `{ink, graph0}` for the design
  pass at the requested band. The draft ink is blue-line (`origin: 'draft'`), every stroke labelled, so PERCEIVE is
  skipped (all components pinned).
- **Rules check** (`POST /api/v2/games/{id}/rules/check`, §8.2): call `rules_check {levels, rules}` with the game's
  current levels; return `affected` as is (the new optional fields `repairable`, `repairs`, `level_hash` let the UI
  show "the designer can fix these" per level). Applying the repair = rebuild each level `tier: faithful`,
  `repairUnsolvable: true` under the new rules (`core.repairUnder(level, rules)` does exactly that).
- **Library versions** ("Update levels to v3", §8.1): call `library_check {levels, type, library}` with the game's
  levels and the new type version; save each `updated[].level` as the level's next version and list `broken` (key
  `library.update_breaks`, message requested from F below).
- **Remix drafts**: pass the parent `LevelV2` as `parent` to `perceive_heuristic`, `build`, `build_tiers`,
  `apply_plan` inputs and the publish rebuild, and set `InkDoc.parent = {level_id, version, level_hash}`. A paper
  remix scan then inherits the parent's strokes and object ids (§6.5); canvas remixes get the id mapping.
- **Library**: pass the game's `library` (all versions the levels pin) to `perceive_heuristic`, `build*` and
  `merge_perception` (new optional param): stamps with `lib`, H21 symbol matches and PERCEIVE's `BLibrary` names
  become `use_library` instances.
- **Seed** (`seed_v2.py`): `shared/starter/dist/index.json` lists the games, their level files in order and L5's
  `unlock_after`. Starter World levels are `lvl_world_l1..l5` in `game_world` (D-2's ids); Classic Starter's migrated
  levels moved to `dist/classic/` (so the `dist/*.level.json` glob is Starter World only) and keep the v1 ids in
  `game_classic`. The remix showcase (L1 "Challenging", "speedrun") is not built here: it is
  `build_tiers` on L1's ink at Normal, authored `maya` / `sam`.

## Lane F (messages, Studio)

New keys the core emits (kid-facing, ≤ 12 words):

| Key | Args | Suggested sentence |
|---|---|---|
| `library.option` | name | "{name}" (an `is_library` Ask option when the game has several types) |
| `warning.library_missing` | about | "This one is from an older library. Pick it again." |
| `library.update_breaks` | - | "The new version makes this level impossible." |

Starter World signs are drawn text strokes (`role: text`); nothing to translate.

## Lane E (art)

- A library instance (`SceneObject.lib = {type_id, version}`) should be drawn with the type's art
  (`LibraryType.art.strokes`, scaled to `art.size_cells`, from `level.embedded_library`), unless the instance kept
  its own drawing (`use_library` op with `x_own_art: true`). The object's shape is already the type's size.
- `firebar` entities can now come from a kid or draft `saw`-role drawing (`rule: {kind: 'firebar'}`), not only C6.

## Lane C (paper)

- `computeComponents` (core) no longer unites two dots, nor two strokes with different `label`s. Paper keeps its own
  grouping through `ensureComponents`, so `features.py` only needs the dot rule if raster ingest starts relying on the
  core's grouping.
