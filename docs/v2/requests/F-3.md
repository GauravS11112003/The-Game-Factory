# F-3: HTTP details the v2 web app relies on (lane D)

The web client is `web/src/app/api.ts`. It is tolerant of several shapes, but these are what it sends and prefers.

## POST /api/v2/builds (multipart)
- Canvas: part `ink` is a **file part** (`ink.json`, `application/json`) holding the InkDoc. Please accept a plain
  string field too.
- Paper: part `photos` (repeatable; one photo today), JPEG ≤ 2400 px long edge.
- Optional fields: `typed_rules` (JSON array of `{text, target}`), `game_id`, `parent_id`, `title`,
  `dial` (`faithful|polished|challenging`, the `Dial` enum) and `band` (`normal|hard`, only with `challenging`).
- When `inkFromStrokes` is not available in the browser, `ink.components` may be `[]`; the worker should derive
  components from `strokes` in that case.

## Answers, edits, critic
- `POST /drafts/{id}/answers {ask_id, choice}`: `choice` is the option id, or the tapped object id for `tap_target`
  options (the UI also applies the matching `link` / `set_role` op locally as a kid edit).
- `PUT /drafts/{id}/edits {statuses, kid_edits}`: `kid_edits` are bare `EditOp`s (re-labels, answers, make_mine,
  Fix-it candidate ops). Please re-emit `tier` events for the rebuilt tiers into the draft's event log after a PUT;
  the client polls `GET /drafts/{id}?since=` for them when its local core cannot rebuild.
- `POST /drafts/{id}/critic` and `/redesign` return `{build_id}`; the client follows
  `GET /builds/{build_id}/events` and reads `note`, `suggestions` and `ask` from it (any seq).

## Feed, game, tree, runs (tolerant parsing; preferred shapes)
- `GET /games?sort=` → `{games: [{id, title, author, created_at, levels: [LevelCard…]}], levels?: [LevelCard…]}`.
- `LevelCard` = `{id, version, title, author, band, score, clear_rate, best_ms, screens, order_index, parent_id,
  game_id, thumbnail_url, safety}`. If `thumbnail_url` is missing, the client renders `GET /levels/{id}` itself and
  caches it in IndexedDB.
- `GET /games/{id}` → `{id, title, author, levels: [LevelCard…]}` ordered by `order_index`.
- `GET /games/{id}/rules` → `GameRules` (or `{rules: GameRules}`).
- `GET /levels/{id}/tree` → a nested node `{id, version, title, author, changed: [{object_id, bbox}], children: […]}`.
- `GET /levels/{id}/runs` → `{runs: [{run_id, player, time_ms, deaths, coins, big_coins, level_version, board}]}`.
- `GET /runs/{run_id}` → `{run, replay, sprite_url}`.

## Errors
Bodies `{message_key, args}` (or FastAPI's `{detail: {message_key, args}}`) are shown through `messages.json`.
Unknown keys fall back to a generic sentence by status code. A new key used by the client: `error.network`.
