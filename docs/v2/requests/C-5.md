# C-5: wiring lane C's wave-2 work into the platform (lane D)

Lane C · See. Status: open. The APIs are in C-3. Everything below is in lane D's files.

## 1. Remix and extend packs need the parent before the build

`run_scan_v2` now stitches a remix or extend pack onto its parent level. It adds the parent's strokes (origin
`parent`), keeps the parent's screen for every sheet not scanned, appends the extend screen and sets `ink.parent`.

- **Pass the parent.** Call it with `parent=self.parent_level` when the request had a `parent_id`.
- **When the pack names the parent but the request does not:**
  - The scanner loads the parent itself, from `app.db_v2.get_level_row`, and returns it as `ScanV2.parent`.
  - `load_context()` has run before `scan()`, so `self.parent_level` is still `None` at that point.
  - Please adopt `scan.parent`: set `self.parent_level`, write `parent.json`, and set the state's `parent_id` and the
    parent's rules, all **before** `perceive_heuristic` and the first `build`.
  - Otherwise `BuildInput.parent` is null for paper remixes.
- **Packs table.** `pack_info()` reads `kind`, `k`, `game_id` and `parent_id` from it; nothing changes there.

## 2. Draft state: complete packs and publishing

`ScanV2.complete` and `ScanV2.playable_screens` are new.

- **Store them in the draft state.** The level is playable as soon as `playable_screens ≥ 1`.
- **Publishing requires all k sheets** (§6.4: "Publishing requires all k sheets and a goal"). This check is
  currently not enforced. Please return `409 {message_key: "publish.needs_all_sheets", args: {missing}}` when
  `complete` is false. Lane F needs to add the key.
- **Inherited remix screens count as present.** Each carries `SheetInfo.x_inherited: true`.

## 3. Endpoints that are still 501 stubs

| Endpoint | Call |
|---|---|
| `POST /api/v2/packs {kind, k, game_id?, parent_id?}` | Insert the `packs` row. Reject an `extend` whose parent already has 6 screens with `409 error.level_too_long`. |
| `GET /api/v2/templates/pack/{pack_id}.pdf` | `make_pack_pdf(PackInfo(...), parent_level, title=game_title)`. The parent is needed for `remix` and `extend`. |
| `GET /api/v2/packs/{pack_id}` | Sheet status. Use the drafts that scanned the pack (`state.pack_id`), plus `SheetInfo.index` and `x_inherited`. |
| `GET /api/v2/templates/rules.pdf?game=` | `make_rules_pdf(game_id, current=game_rules, title=game_title)` |
| `GET /api/v2/templates/library.pdf?game=` | `make_library_pdf(game_id, latest_types, title=None)` |
| `POST /api/v2/scan/rules-sheet` (photo) | `await asyncio.to_thread(read_rules_sheet, data, work_dir)` returns `{patch, asks}`. See the notes below. |
| `POST /api/v2/scan/library-sheet` (photo) | `await asyncio.to_thread(read_library_sheet_detail, data, work_dir)` returns `{drafts: drafts_json(res.drafts)}`. See the notes below. |

**Errors.** Both scan endpoints raise `ScanV2Error`. Its `.message` is the 4xx body: `error.wrong_sheet`,
`error.not_rules_sheet`, `error.not_library_sheet`, `error.no_drawing`, `error.paper_missing`, `error.upload_failed`.

**Rules sheet.**
- Check `result.x_game_id` against the game when the QR was read.
- `x_story_crop` is a JPEG of the "My world is…" lines. When `x_story_ink` is true, it can go to a small model read
  for the game's title and blurb (§8.2: "read by PERCEIVE").
- Applying the patch: `apply_rules_patch(current_rules, patch)`, then `PUT /games/{id}/rules`, which bumps `version`.

**Library sheet.**
- The name lines are handwriting: `LibraryBoxRead.name_jpeg`, or the `library/name<box>.jpg` file when `work_dir` is
  given.
- With the model on, read them (one call over all the crops is enough) and set `draft.name` and
  `name_source: "model"`.
- Offline, the names stay "Creature N" and the kid types them.
- On confirm, `draft_to_library_type(draft, type_id=..., game_id=..., author=..., used_letters=[letters already in
  the game])` builds the immutable type for `POST /games/{id}/library`.

## 4. PERCEIVE on remix screens that were not scanned

`tiles_for(ink)` keeps a tile per inherited remix screen, because the parent's strokes there are ink the build has to
understand. That costs one PERCEIVE call per screen.

Once lane B's `remixDiff` restores the parent's roles (C-6 §2), you can skip tiles whose `SheetInfo.x_inherited` is
true and whose components are all parent ink. Until then, keep them.
