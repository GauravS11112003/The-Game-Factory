# F-1: key → door links from the editor chip (lane B)

**Need.** §7.11 "What does it do?" has the chip "key → tap a door". `InkStroke` has `label` (Role) and `rule` (Behavior),
but `Behavior` has no key/door variant, so a kid's explicit link has no field in the format.

**What lane F emits now (format-valid).** On every stroke of the key:
- `label: "key"`;
- `x_opens: "<door stroke id>"` (an `x_*` extension key, allowed by §2.1 and CONTRACTS §3.1).

The door stroke gets `label: "door"`.

**Ask.**
1. `perceiveHeuristic` (or the U-edit pass) turns `x_opens` into a U5 `link {key, door}` with `by: kid`, conf 1.0, using the
   objects that contain those strokes, so PERCEIVE skips both components.
2. Optionally promote it to a first-class `InkStroke.opens?: string` in a contract PR; lane F will switch the field name.

**Lanes:** B (perception), D (nothing; it passes the InkDoc through).
