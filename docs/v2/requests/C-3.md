## Paper levels

`app.cv.scan_v2.run_scan_v2(images, pack, work_dir, *, pack_lookup=None, parent=None, parent_lookup=None) -> ScanV2`

**Arguments**
- `pack`: a `PackInfo(pack_id, kind, k, game_id, parent_id)`, or `None`.
  - With `None`, `pack_lookup(pack_id) -> PackInfo | None` is called with the pack id read from the QR codes.
  - A v1 `dal1|lvl|<id>` sheet resolves to a remix of that level.
- `parent` (new): the parent LevelV2 dict for a `remix` or `extend` pack. Without it, `parent_lookup(parent_id)` is
  asked, and without that the scanner reads `app.db_v2.get_level_row(parent_id)["level"]` (read-only).

**What the scanner does across photos** (`app/cv/stitch.py`)
- Photos can come in any order. Each one's sheet number comes from its QR. When the QR cannot be read, it comes from
  the printed pack map (sheets 2..k), or from the character and rules boxes (sheet 1).
- Photos that still have no place are put where their stroke ends best meet the neighbouring sheets' ends.
- Two photos of one sheet: the newest wins (`warning.duplicate_sheet`).
- **new / game**: a missing sheet becomes an empty screen with `warning.sheet_missing {n, k}`.
- **remix**:
  - `world.screens = max(k, parent screens)`.
  - Every sheet that was not scanned keeps the parent's screen (no warning; its `SheetInfo` carries `x_inherited: true`).
  - The parent's strokes are in the InkDoc with origin `parent` (ids `p1..`), as in the canvas remix. The parent's
    character is used when sheet 1 has none.
- **extend**:
  - The one sheet adds screen `k_parent + 1`, and its drawing area starts at world x `48·k_parent − 2`.
  - The parent's strokes are included as above.
  - A parent that already has 6 screens raises `ScanV2Error("error.level_too_long", {max: 6})`.
- When the parent cannot be found, the scanner warns `warning.parent_unavailable` and builds from the new ink only.

**Return value**
- `ScanV2.ink`: the InkDoc, with `source: "paper"`.
  - `parent` is now set (a `ParentRef`) whenever a parent level was stitched in.
  - `typed_rules` stays empty; D merges the form's typed rules.
- `ScanV2.sheets`:
  - one `SheetInfo` per world screen that has a photo, plus one per inherited screen;
  - `index` is the 0-based screen;
  - `photo_url` is **draft-relative**, `sheets/<index + 1>.jpg`.
- `ScanV2.files`:
  - `{"sheet:<screen>": rectified sheet JPEG, "character:<screen>": sprite PNG}`, with the screen 1-based;
  - the files are already named `sheets/<screen>.jpg` inside `work_dir`.
- `ScanV2.seams` (new): a `SeamReport` per seam, `{seam_x, left, pairs: [{a, b, y, dy, color}], unmatched}`. These
  are the N11 join candidates (`as_dict()` for JSON).
- `ScanV2.complete` (new): every sheet of the pack is there. Publishing requires all k sheets (§6.4).
- `ScanV2.playable_screens` (new): screens in the contiguous run from sheet 1.
- `ScanV2.parent` (new): the parent level dict that was used.
- `ScanV2.warnings`: MessageRefs (C-2, C-4).

**Failures.** `ScanV2Error.message` is the kid-facing `MessageRef`:
- `error.paper_missing`
- `error.no_drawing`
- `error.upload_failed`
- `error.level_too_long`

**Threads.** The call is synchronous and runs sheets in a thread pool, so call it with `asyncio.to_thread`.

## Rules Sheet (§8.2)

`app.cv.checkbox.read_rules_sheet(img, work_dir=None) -> RulesSheetResult`

`patch` is a partial GameRules. Only the rows with exactly one tick are in it. Abilities are nested, e.g.
`{"physics_profile": "v2-snappy", "abilities": {"double_jump": true}, "lives": 3, "theme": "notebook"}`.

**`asks`** (MessageRefs; the row stays out of the patch):
- `ask.rules_two_ticks {row, a, b, n}`
- `ask.rules_unsure {row, option}` (a faint mark in a row with no tick)

**Extension keys:**
- `x_game_id`: from the QR
- `x_values`: group → value
- `x_story_ink`: whether anything is written on the "My world is…" lines
- `x_story_crop`: a `work_dir`-relative JPEG, `rules/story.jpg`, for PERCEIVE
- `x_warnings`

**More.**
- `read_rules_sheet_detail(img, work_dir)` returns the crop bytes (`story_jpeg`) and every box's fill.
- `apply_rules_patch(rules, patch) -> dict` deep-merges the patch and validates the result as `GameRules`. The server
  bumps `version`.
- Raises `ScanV2Error`:
  - `error.wrong_sheet {expected, got}`: the QR is a level or library sheet;
  - `error.not_rules_sheet`: under half of the boxes were found;
  - plus the paper errors above.

## Library Sheet (§8.1)

`app.cv.checkbox.read_library_sheet(img, work_dir=None) -> list[LibraryDraft]`, with one draft per filled box (out
of 6).

**`LibraryDraft` fields** (pydantic, in `checkbox.py`):
- `box`
- `name`: "Creature N" until PERCEIVE or the kid names it; `name_source: "default"`
- `name_has_ink`
- `name_crop`: `library/name<box>.jpg`, written when `work_dir` is given and the line has ink
- `letter`: None; the server assigns it
- `kind: "creature"`
- `archetype`: walker | hopper | flyer | shooter | chaser | crusher, or None (stays still)
- `speed`: slow | normal | fast
- `spiky`
- `behavior`: the typed Behavior, with numbers from the §5.6 grids
- `collision: "none"`
- `art`: `{strokes, size_cells}`. The strokes start at (0, 0); the long side is 1.75 cells and the short side at
  least 0.75.
- `symbol`: a `LibrarySymbol` when all 3 symbol cells are drawn, else None
- `symbol_samples`
- `ticks`: box → fill
- `asks`:
  - `ask.library_two_moves {box, a, b}`
  - `ask.library_slow_and_fast {box}`
  - `ask.library_unsure {box, option}`
- `warnings`:
  - `warning.library_no_drawing {box}`
  - `warning.library_symbol_incomplete {box, count}`
  - `warning.library_speed_without_move {box}`

**More.**
- `read_library_sheet_detail` also returns the name-line JPEG bytes per box.
- `drafts_json(drafts)` gives the JSON for `{drafts}`.
- `draft_to_library_type(draft, type_id=, game_id=, author=, used_letters=, version=1, created_at=, name=)` gives
  the immutable `LibraryType`. The letter is the first free letter of the name (`assign_letter`).
- Raises `ScanV2Error`:
  - `error.wrong_sheet`
  - `error.not_library_sheet`
  - `error.no_drawing`: every box is empty

## PERCEIVE tiles and the library strip

`app.cv.annotate`:
- `tiles_for(ink) -> [Tile]` gives one tile per paper sheet (`sheet<n>`), inherited remix screens included, or one per
  2 canvas screens (`t<j>`).
- `render_annotated(ink, tile, px_per_cell=24, *, labels=True, tiles=None) -> JPEG bytes`. Pass the same `tiles` for
  every tile of one build.
- `component_rows(ink, tile, tiles)` and `component_table(rows)` build the compact component table.
- **`render_library_strip(types) -> JPEG bytes`** (new).
  - It takes LibraryType models or dicts.
  - Each type becomes a card with its art in its own inks, its circled letter, name, kind, behavior words, version and
    paper symbol.
  - It returns `b""` for an empty library. The orchestrator already calls it.

## Printing

`app.template.generate_v2`:
- `make_pack_pdf(pack, parent=None, *, title=None) -> PDF bytes`
  - `new` / `game`: k blank sheets. `title` replaces "DRAW A LEVEL", for example with the game's title.
  - `remix`: k sheets with the parent's ink in gray (pickups and goals as outlines) and neighbour dashes at the seams.
  - `extend`: 1 sheet. Its left 2 columns show the parent in gray, a dashed line marks where the parent ends, and
    dashes show its terrain heights there. It raises `ValueError` when the parent already has 6 screens.
- `make_rules_pdf(game_id, *, current=None, title=None) -> PDF bytes`: one page. `current` (GameRules or a dict)
  prints a gray "now" under each current choice.
- `make_library_pdf(game_id, types=(), *, title=None) -> PDF bytes`: the Library Sheet, plus a reference page with the
  game's existing types (art, name, circled letter, behavior, symbol) when there are any.

QR helpers in `app.template.spec_v2`:
- `parse_qr(payload) -> QrInfo | None`
- `pack_payload(pack_id, n, k)`, `rules_payload(game_id)`, `library_payload(game_id)`. Ids must match
  `[A-Za-z0-9_-]{4,32}`.
- `blank_pack_id()` (`"blank"`) is the 1-sheet sheet that needs no server pack.
