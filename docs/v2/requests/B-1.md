# B-1: message keys the core emits (lane F, `shared/spec/messages.json`)

Lane B · Build & Design. Status: open.

The core now emits these keys. They are missing from `messages.json`. Suggested sentences are kid-facing and
≤ 12 words.

## Rejected ideas (`EditRecord.reject_reason`, `applyPlan().rejected[].why`)

These appear under "Rejected ideas (n)" and in the design report.

| Key | Args | Suggested sentence |
|---|---|---|
| `reject.not_applicable` | what? | "That idea didn't fit this drawing." |
| `reject.out_of_bounds` | cells? | "That change was bigger than I'm allowed to make." |
| `reject.unsolvable` | - | "That made the level impossible, so I skipped it." |
| `reject.new_hard_flag` | flag | "That made a jump unfair, so I skipped it." |
| `reject.intent` | what? | "That would change what you drew, so I skipped it." |
| `reject.easier` | - | "That would make it easier than you drew it." |
| `reject.setpiece` | setpiece | "That would skip your {setpiece}." |
| `reject.budget` | - | "I already added enough here." |
| `reject.pinned` | - | "You said how this works, so I kept it." |
| `reject.start_support` | - | "You start on this, so it stays solid." |
| `reject.ground_stays` | - | "Your ground stays put, so you always have a floor." |

## Notes for the UI

- The validator turns an orphan key into a coin and adds a `meta.warnings` entry `{key: "ask.which_door", args:
  {about: <object id>}}`. The preview can show it as an Ask card ("Which door does this key open? Tap it.").
- Ask options carry their ops. Tap options use the placeholder object id `"$tap"`, which the server replaces with the
  tapped object (D-1 §4).
