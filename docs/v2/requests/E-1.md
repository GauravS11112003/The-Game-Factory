# E-1: what the v2 engine needs from the core Sim (lane A) and the compiler (lane B)

Lane E's `mountGame` (`web/src/engine/`) drives `createSim` at a fixed 60 Hz and draws ArtDoc sprites at
`SimView` positions. These are the assumptions it makes. Until `createSim` lands, the engine uses a static stand-in
(`web/src/engine/simhost.ts`), so every screen stays usable.

## Lane A (Sim)

1. **Entity coordinates.** `EntityView.x/y` uses the same convention as the compiled entity's own `x/y`. The engine
   bakes each sprite relative to the spawn `x/y` and places it at `EntityView.x/y`, so the convention cancels out.
   Spikes are static, so the art keeps their compiled position. The convention the art uses is:
   - centre: coin, big_coin, key, saw, firebar anchor, hint_arrow;
   - feet centre (x centre, y = top of the support): enemy, checkpoint, goal, spring, player_start;
   - top-left of the one-row AABB: moving_platform, crumble, falling_platform, door (w × h).
2. **Restart from checkpoint (R / Select / HUD button).** *Status: adopted by lane A (`IN_RESTART = 32`,
   `INPUT_MASK = 63`, codec `BITS_MASK = 0x3f`); the fallback below stays for older cores.* This should count as a recorded death, the way Celeste
   handles it. The engine sends **input bit 32 (`RESTART`)** for one frame. Please treat it as "start the normal
   death sequence now, cause `restart`", and emit the `death` event on that same step. The bit is stored in the
   replay like any other input (the u8 bits byte already has room), so `verifyRun` reproduces it.
   - While the sim ignores the bit (no `death` that step), the engine clears the bit from the recording and falls
     back to rewinding to a snapshot taken at checkpoint activation, truncating the replay to that frame.
   - The replay then still verifies, but the time and deaths of the rewound part are lost. The `win` payload reports
     `rewound > 0` so boards can ignore that run.
   - `replay/codec.ts` currently rejects input bytes above `0x1f`. Please widen `BITS_MASK` to `0x3f`, so RESTART
     survives encoding. Until then the engine masks the bit when encoding, and such a run will not verify.
3. **Events the engine uses.** Each listed event should carry `x/y` (cells) where it happens, and `id` where an entity
   is involved:
   - `jump`, `double_jump`, `land` (the engine reads impact from the previous frame's `vy`), `skid`;
   - `coin`, `big_coin`, `big_coin_banked`, `key`;
   - `stomp` (with `chain`), `hit`, `death` (with `cause`), `respawn`;
   - `checkpoint`, `spring`, `crumble`, `door_open`;
   - `win`, `lose`, `timer_warn`, `entity_error`.
4. **Player states.** `player.state` should be `'dead'` for the whole death sequence and `'respawn'` while
   reassembling. Shards burst on `death` and gather on `respawn`. If no `respawn` arrives within 750 ms after the
   state leaves `dead`, the engine reassembles at the player's position. The engine glides the camera (≤ 300 ms)
   whenever `camera().x` jumps by more than 3 cells.
5. **Firebar.** The engine draws the balls at angle `phase + speed_deg_s · frame / 60` (degrees), with ball `i` at
   radius `10 px · (i + 0.6)`. Please use the same angle and radius, or put the angle in degrees in
   `EntityView.phase`.
6. **Projectiles.** Shooter ink blobs (and anything else the sim spawns at runtime) should appear in
   `SimView.entities` with a unique `id` that is not a compiled entity id, plus `active: true`. The engine draws
   each one as an ink blob and removes it once it is gone from the list. Today blob ids are `<owner>#blob<k>`, where `k` is the array index,
   so ids shift when an earlier blob dies and interpolation jumps for one frame. A per-sim counter id would fix it.
7. **Camera.** `Sim.camera()` is used when it is available. If it throws, the engine falls back to its own §6.2
   follow rule, which is not deterministic. That is acceptable for rendering only.

## Lane B (compile)

1. `entity.sprite` should name the scene object whose strokes draw the entity, or `entity.id` should equal that
   object's id. Its `rel.parts` and every object with `rel.part_of` pointing to it are drawn into the same sprite.
2. **`ESpikes` facing left or right.** The art follows lane A's convention (`sim/world.ts`, A-1): for a vertical
   face, `x0..x1` is the vertical extent and `y` is the face's x. Please compile vertical strips that way.
3. `surface` objects with `fill: "to_top"` are aligned on their underside (ceilings). Every other surface and every
   wall is aligned on its top, from the compiled tiles.
