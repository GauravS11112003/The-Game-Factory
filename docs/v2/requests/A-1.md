# A-1: Sim geometry conventions, report conventions, new lane-A helpers

From lane A (Sim & Bot). Affects lane B (compile, design, CLI), lane E (engine views, ghosts), lane D (runs).
No schema change is required; item 1 asks lane B to document (and compile to) the conventions the Sim reads.

## 1. Entity geometry the Sim reads (`web/src/core/sim/world.ts`)

PLAN_V2 §2.1 fixes cells, y down and the feet line, but not every entity's anchor. The Sim uses:

| Entity | (x, y) means | Size |
|---|---|---|
| `player_start`, `checkpoint` | x centre, y feet line | checkpoint trigger = [x−0.5, y−2.5, x+0.5, y] |
| `enemy` (every archetype) | x centre, y feet line (bottom of the AABB) | `w × h` cells; a flyer's pattern is centred on its initial body centre; `bounds` = range of the **centre** x in cells (as `compile.ts` `patrolBounds` emits it) |
| `spring` | x centre, y feet line | up: [x−w/2, y−0.5, x+w/2, y]; side: 1 cell tall |
| `coin`, `big_coin`, `key`, `saw`, `firebar`, `hint_arrow` | centre | coin pickup r = 5 px + 6 px magnet; big coin / key r = 8 + 6 px; saw hit r = 0.8·r |
| `door` | **top-left** | `w × h` |
| `moving_platform`, `crumble`, `falling_platform` | **top-left** | `w × 1` row; a moving platform's `path` lists top-left positions (if `path[0]` ≠ (x, y), (x, y) is prepended) |
| `goal` | `trigger` rect is the win box | - |
| `spikes` | `x0..x1` run **along the face**, `y` is the **face line** | 6 px band, 2 px end inset |

**Spikes on left/right faces (documentation only):** `ESpikes` has only `x0, x1, y`. For vertical faces the Sim
reads `x0..x1` as the **vertical** extent (cells) and `y` as the face's x, which is what `build/compile.ts`
`spikesEntity` already emits. Please state it in `docs/spec/level-format-v2.md` so third-party engines agree.

Key ↔ door: either side may name the other (`key.door`, `door.key`); a single unnamed pair links implicitly. A door
opens when the player touches it while holding one of its keys.

`compiled.triggers` supported: `collect:<id>`, `touch:<id>`, `timer:<s>` → `open:<door id>`, `win`, `lose`.
`timer:<s> → lose` is the lose timer (counts from the first input).

## 2. PlaytestReport conventions (`web/src/core/bot/`)

- `route[i].from / to`: takeoff and landing **feet** positions (cells, 2 decimals) for jumps; node positions for walks.
  Consecutive walks are merged into one step. `w_f / h_f / phi_f` ≥ 999 mean "unbounded"; `phi_f` is null when
  the action is untimed.
- `trace`: run-length pairs `[run, bits, run, bits, …]` of the bot's replay of its own route (5-bit inputs).
  `replay/verify.ts` `traceToInputs(trace)` + `makeReplay(level, inputs, CORE_VERSION)` turn it into a `Replay`.
- `reachable`: `"x,y"` feet positions in cells, de-duplicated per 4 px (F-2 form 1); `frontier.reached` uses the
  same positions.
- `segments`: split after each route step that activates a checkpoint; ids `seg0…`.
- `slots.*`: x centre; y feet for grounded slots (checkpoint, enemy, spring, step, spikes) and centre for floating
  ones (coin, risk, hazard, hint). Tags carry context: coin arcs `action:<route i>`, `n:<count>`, `k:<index>`;
  enemy slots list the archetypes that fit (`walker`, `chaser`, `hopper`, `shooter`, `flyer`, `crusher`) with the
  flat extent in `x0..x1`; hazard slots `saw`/`firebar` or `lava` (pit extent in `x0..x1`); spikes slots have
  `face: top`, `x0..x1`, `w`; step/spring slots carry the failure kind and `dir:±1`; hint slots `dir:<right|left|down>`.
- `flags[*].fix_cids` are left empty for the design layer to fill. Severity of `softlock`, `long_segment`,
  `skippable_setpiece`, `long_flat` follows the tier (see `AnalyzeOptions.tier`).
- `approx: true` when the deterministic frame budget ran out or the route replay diverged.

## 3. `AnalyzeOptions` additions (optional, backward compatible)

- `tier?: Tier` (default `level.design.tier`, else `faithful`) for flag severities.
- `budget?: number` multiplier of the simulated-frame budget (`BOT_BUDGET` in `bot/index.ts`).

## 4. Helpers lane B / E / D can call

- `bot/index.ts`: `measureEnvelope(profileId)` (apex / distance / tap hop / `g_max` table, measured in the Sim; for
  `cli.ts envelope`), `gMaxTable(profileId)` (runway 0..6 cells), `freeFlight`, `template` (free-flight arcs).
- `difficulty/model.ts`: `miss`, `pFail`, `deathProb`, `segmentStats`, `levelStats`, `bandOf`, `scoreOf`, `parMs`,
  `bandRange`, `readout` (message key + args for `readout.pill` / `readout.rarely_fall`), `beforeAfter`,
  `dialTarget`, `sawtooth`, `segmentTargets`, `meetsTarget`, `targetGap`, `wishTier`, `fmtClock`, `fmtRunClock`.
- `replay/index.ts`: `verifyRunDetail` (verdict + reason), `makeReplay`, `traceToInputs`, `inputsToTrace`,
  `MAX_RUN_FRAMES`.
- `sim/index.ts`: `SimCore` (the class behind `createSim`), `clockMs(frames)` (the one ms formula the HUD, the
  results card and `verifyRun` share), input bit constants `IN_L IN_R IN_J IN_RUN IN_D`.

## 5. Additive runtime fields for lane E (`sim/types.ts`)

- `SimView`: `clock_frames`, `time_ms`, `big_coins_total`, `keys`.
- `PlayerView`: `dead_f`, `hitstop_f`, `hp`, `ground`.
- `EntityView`: `kind`, `state`, `facing`, `vx`, `vy`, `r`, `angle` (turns), `balls`, `t`.
- `CameraState`: `mode`, `walk_px_s`. `sim.camera()` is already stepped by `cameraStep` every frame.
- `SimEvent` adds `bonk`, `drop_through`, `shoot`, `crusher_land`, `hop`, `alert`, `life`, `game_over`, `falling`,
  `start_clock`; `stomp` carries `chain`, `coin` carries the coin count in `n`.

## 6. Answers to E-1 and F-2 (done in lane A's files)

- **RESTART input bit 32** (E-1 item 2): `sim/types.ts` `IN_RESTART = 32`, `INPUT_MASK = 63`. The bit starts the normal
  death sequence on that step (`death` event, cause `restart`, counted in `deaths` and lives). `replay/codec.ts`
  `BITS_MASK` is now `0x3f`, so such runs encode and verify. Lane B: please record bit 32 next to "L R J RUN D" in
  `docs/v2/CONTRACTS.md` §3.6 (contract addition; the byte layout is unchanged).
- **Death timeline** (E-1 item 4): `player.state` is `dead` for 33 frames at the death spot, then the world resets,
  the player is placed at the respawn point and `respawn` fires, and `player.state` is `respawn` for 12 frames
  (reassembly, 200 ms) before control returns; 45 frames = 0.75 s in total. Jump after 15 frames (250 ms) skips to
  control. `player.dead_f` counts frames through both parts.
- **Event positions** (E-1 item 3): every listed event carries `x/y` (cells); `big_coin_banked`, `door_open`, `lose` and
  `timer_warn` gained them.
- **Firebar** (E-1 item 5): ball `k` sits at `10 px · (k + 0.6)` from the anchor (`FIREBAR_STEP`, `FIREBAR_OFF` in
  `sim/core.ts`). The angle runs on the entity clock (which resets on respawn), so read it from the view:
  `EntityView.phase` = angle in degrees, `EntityView.angle` = the same in turns, `EntityView.balls` = ball centres.
- **Blob ids** (E-1 item 6): `<owner id>#blob<n>` with a per-sim counter, stable for the blob's life.
