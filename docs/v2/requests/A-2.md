# A-2: game rules in the bot and the model, run verification with claims, replay and ghost hooks

From lane A (Sim & Bot), wave 2. No schema change. The new fields are extra keys on results that are already JSON.

## 1. What changed in lane A (for every lane)

**Game rules (§5.3, §5.5, §8.2).** `level.rules` is the resolved per-game snapshot. The Sim already applied it:
profile, run, stomp, double jump (vy now from `ABILITIES.double_jump.vy`), fast fall, hearts 1..3 and lives 3/5.
The bot and the difficulty model now apply it too:

- A **hit is a failed action** for the bot, even when hearts remain. Routes therefore never take damage.
  - Each failure is classed **soft** or **hard**.
    - Soft (a heart absorbs it): spikes, enemy, saw, firebar, blob, hazard cell.
    - Hard: pit, lava, crush, crusher, timer.
  - `StepWindows` / `ActionWindows` gain `Ls`, the soft share of the failing samples (≤ `L`).
- **Hearts** (`difficulty/model.ts`).
  - `deathProbHearts(a, σ, hearts)`, `segmentDeaths(actions, σ, hearts)` and `segmentStats(s, σ, hearts = 1)`.
  - The heart distribution is carried from action to action, so a hit is retried with one heart less, and the last
    heart kills.
  - With hearts = 1 every number is unchanged.
  - `SegmentStats.d[]` holds the per-action death probability. The report's `p_death_casual` / `p_death_skilled` use it.
- **Lives.** `levelStats(segs, { lives })` turns `casual_clear_s` into the expected time with game-over restarts (a
  renewal over passes) and adds `p_game_over`. With lives off nothing changes.
- **Reach of the rules.** `bot/envelope.ts`:
  - `reachFor(profile, { run, double_jump })` gives the highest ledge, the standing apex, `g_max(runway)`, the best gap
    and the runway it needs (measured in the Sim with the double jump, cached).
  - `gMaxTable` and `measureEnvelope` take the abilities.
  - `jumpArcs(profile, abilities)` returns the arcs the rules screen can draw (stand / walk / run, plus the double-jump
    versions).
  - `template` / `freeFlight` take a double-jump frame.
- **Frontier.** Quotes the rules' reach, for example "You can jump 6" with the double jump. When running is off, or
  the run-up is already long enough, it uses the new key **`frontier.too_far`** {need, max} instead of
  `frontier.needs_run_up`.
- **Bot speed, exact.** Jump variants that differ only in hold / double-jump timing share their common prefix
  (`Explorer.runGroup`). This covers the explore action set, the 45-hold sweep and the hold fallbacks of the takeoff
  sweep. Phase samples share one idle prefix. Every outcome equals playing the variant alone. This replaces the
  approximate trajectory-template fast path of §4.1, so the 10,000-sample property test is not needed for
  correctness.
- **Fast-mode windows.** A moving takeoff in the middle of a surface now gets a short takeoff sweep (±4..32 px), so
  fast-mode C no longer reads low there.
- **`report.trace` replays from frame 0**, even with an airborne spawn: the spawn's settle inputs come first.
  `replayOfTrace(level, report.trace)` gives the bot's run as a `Replay`.
- **`PlayerView.running`** is now set (Run held and allowed). The lose-timer warning fires once at ≤ 10 s left, so a
  timer shorter than 10 s warns at once. `n` is the whole seconds left.

**Replays (§8.4).** `replay/index.ts`:

- `createSim(level, { record: true })`. `sim.inputs()`, `sim.recordingValid()` and `sim.replay()` are optional
  members on `Sim`.
  - The Sim records every byte `step()` consumed.
  - `restore()` to an earlier snapshot truncates the recording.
  - A `startAt` ("play from here") recording is never valid.
- `ReplayRecorder` covers hosts that drive the Sim themselves: `push`, `mark`/`truncate`, `firstInput`, `tooLong`,
  `replay(level)`.
- `ghostTrack(level, replay)` → `GhostTrack`. It is the run verifyRun sees, re-simulated once into per-frame poses.
  - `pose(f)` and `positionLerp(f, a)` (never across a respawn teleport).
  - `raceFrame(playerFrame, playerClock0)` maps the player's frame to the ghost's for a race where both clocks start
    with the first input.
  - `split(frame, x)` / `splitClock(clockFrames, x)` give the live lead in frames and ms.
  - Also `eventsBetween(a, b)`, `over(f)`, and the ghost's `time_ms` / `deaths` / `coins` / `big_coins` / `finished`.
- `simulateInputs(level, inputs)` is the one re-simulation loop that verifyRun and ghost tracks share.
- `traceToInputs` / `inputsToTrace` keep the RESTART bit (mask 63).

**Run verification.** `verifyRun(level, replay, claimed?)` returns a superset of `RunVerdict`:

- `accepted` is true when the run is finished and every claimed number (time_ms, deaths, coins, big_coins) matches
  exactly.
- `reason`: `ok | bad_input | too_long | frames_mismatch | level_hash | profile_hash | not_finished | claim_mismatch`.
- `mismatch[]` names the fields that differ. Also returned: `win_frame` and `input_frames`.
- The level and profile hashes are accepted when they equal either the recomputed hash or the one stored on the
  level (`meta.level_hash`, `rules.profile_hash`). A stale stored hash therefore never rejects an honest run.

## 2. Requests

### Lane B (worker, CLI, docs)

1. `worker/dispatch.ts`, `verify_run`: pass the claim through:
   `return core.verifyRun(p.level, p.replay, p.claimed ?? null);`.
2. `cli.ts envelope`: use `measureEnvelope(profile, abilities)` / `reachFor` from `bot/index.ts`. The g_max table can
   now be written per ability set (run off, double jump on).
3. Optional: re-export from `core/index.ts` for the other lanes:
   - `ghostTrack`, `GhostTrack`, `ReplayRecorder`, `replayOfTrace` and `verifyRunDetail` from `replay/index.ts`;
   - `reachFor` and `jumpArcs` from `bot/index.ts`.
4. Repair / design: `reachFor(W.profileId, W.ab)` gives the rules-aware envelope. Lane B's `edits/envelope.ts`
   `gMax`/`hMax` ignore run-off and double jump.
5. Repair search: `localReach(level, from, toX, { margin_c? })` in `bot/index.ts` is the windowed local re-solve of
   §4.1 (±1.5 screens, fast mode, best-first toward `toX`).
   - It returns `{ passed, reached_x, goal, approx, frames }`.
   - Use it for each candidate's "does this fix get past the blocker?" check, then run one full `analyze` on the
     winner, instead of a whole-level analysis per candidate.
   - Entity clocks start at 0 at `from`, so this is a geometric check. A timed blocker still needs the full analysis.
6. `docs/v2/CONTRACTS.md`, please record:
   - the `verify_run` result keys (`accepted`, `reason`, `mismatch`, `win_frame`, `input_frames`);
   - the soft/hard death classes;
   - that a bot route never takes a hit.

### Lane D (runs router, `vision/app/routers/v2/runs.py`)

1. Send the claim to the worker: `pool.call("verify_run", {"level": level, "replay": replay, "claimed": body.claimed.model_dump()})`.
2. Reject with `422 run.rejected {why: verdict["reason"]}` when `verdict.get("accepted") is False`.
   - Today a finished run with tampered claims is accepted, and the server's numbers are stored instead. §8.4 says a
     run counts only when every claimed number matches.
   - Keep storing the server's numbers.
3. `/levels/{id}/runs` could keep the `reason` in the log for tampered runs.

### Lane E (engine)

1. Recording: either keep the scene's own buffer, or use `createSim(level, { record: true })` + `sim.replay()`.
   - The Sim recording truncates itself on `restore()`, so the rewind fallback needs no bookkeeping.
   - `ReplayRecorder` offers the same with `mark()`/`truncate()`.
2. Ghosts: `ghostTrack(level, replay)` precomputes a ghost once (one Sim pass, a few ms for a 2-minute run).
   - Rendering then reads `pose(frame)` instead of stepping up to 3 extra Sims at 60 Hz, which matters on phones.
   - Race sync: `raceFrame(playerFrame, playerClock0)`, with `playerClock0` = the player's `sim.frame` after their
     first input step.
   - Live lead: `splitClock(view.clock_frames, view.player.x)`.
   - Ghost FX: `eventsBetween(prev, cur)` for jumps, landings, deaths and the win.
3. `PlayerView.running` is now available for the run-cycle speed.

### Lane F (messages, rules screen, play screen)

1. `shared/spec/messages.json`: add `"frontier.too_far": "This jump is {need} squares. You can jump {max}."`.
2. Rules screen mini-stage: draw `jumpArcs(profile, abilities)`. Points are cells relative to the takeoff (y < 0 is
   up), one per frame, with `apex_c` / `dist_c`.
3. Play screen: before `submitRun`, the browser core can call `verifyRun(level, replay, claimed)` and show
   `run.rejected` without a round trip when `accepted` is false. The server stays authoritative.
4. "Beat my level": `ghostTrack(level, vs.replay).splitClock(...)` gives the "0.4 s to go!" line live during the
   race. The track's `time_ms` / `deaths` give the banner numbers without trusting the run row.
