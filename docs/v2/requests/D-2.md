# D-2: the rest of the §11.3(e) API (wave 2), and what lane D needs from B, C and F

Lane D · Mind & Platform. Status: open. No schema in `vision/app/spec/**` changed; everything below is either a
response shape, an extension key (`x_*`) or a request to another lane.

## 1. To lane F: new message keys (`shared/spec/messages.json`)

| Key | Suggested sentence | Used by |
|---|---|---|
| `stage.plan` | Planning your level | `stage(cv, start, note_key)` on prompt builds |
| `rules.blocked` | {n} levels would break. Let the designer fix them? | 409 from `PUT /games/{id}/rules?apply=all` |
| `library.update_breaks` | This level can't be finished with the new creature. | `POST /library/{id}/update-levels` `broken[]` |

Existing keys reused: `error.rate_limited` (429 on runs), `publish.needs_all_sheets` (`{k, missing}`),
`rules.needs_run`, `rules.needs_double_jump`, `rules.becomes_unsolvable`, `run.older_version`, `library.creature_n`.

## 2. To lane F: endpoints now live (shapes the client can rely on)

- **`POST /prompt-levels {prompt, game_id?, screens, dial?, band?}`** → `202 {build_id, draft_id, events_url}`.
  - The stream is an ordinary build. It starts with `stage(upload done)` and `stage(cv start, note_key stage.plan)`,
    then `stage(cv done)`. The `ink` event carries the blue-line draft to open in the editor.
  - PERCEIVE is skipped. A blocklisted prompt → `409 publish.safety_flag`.
  - If the core cannot lay out plans yet, the build ends with a fatal `error.not_implemented` and then `done`.
- **Runs.**
  - `POST /levels/{id}/runs`:
    - also returns `coins`, `big_coins`, `board`, `older`;
    - `429 error.rate_limited` (30 per minute per IP);
    - `422 run.rejected` with `why` = `too_long` (over 20 min), `level_hash`, `claim_time`, `claim_deaths`,
      `claim_coins`, `claim_big_coins` or `not_finished`.
  - `GET /levels/{id}/runs`: rows carry `older`. Runs on the current version come first. The response adds
    `creator` (the author's best run or `null`) and `level_version`.
  - `GET /runs/{id}` adds `level_id`; `sprite_url` is the level's player sprite when it has one.
- **Library.**
  - `POST /games/{id}/library`: a new type, or n+1 of the same id in this game. The server sets the circled
    `letter` (unique per game; the first free letter of the name), `game_id`, `version` and `created_at`.
    `size_cells` defaults to the strokes' bbox and `id` defaults to `lt_<hex>`.
  - `GET /library/{id}?v=` → the type plus `x_versions: [1, 2, …]`.
  - `POST /library/{id}/versions` (a partial body is fine) → `201` with the new version.
  - `POST /library/{id}/update-levels?v=` → `{updated: [{level_id, version}], broken: [{level_id, reason_key}]}`.
  - `POST /library/interpret {name, text, ink}` → `{spec, behavior, source}`. `behavior` already holds the grid
    numbers.
- **Rules.**
  - `GET /games/{id}/rules`.
  - `POST /games/{id}/rules/check` with a full or partial `GameRules` →
    `{affected: [{level_id, reason_key, x_title, x_version}], checked, rules}`.
  - `PUT /games/{id}/rules` → `{rules, applied, affected, failed}`:
    - with no query, the change applies to new builds only;
    - `?apply=all` dry-runs first. If anything breaks it answers `409 rules.blocked {args: {n}, affected}`;
    - `?apply=all&repair=1` rebuilds every level with Faithful repairs and saves each as a new version.
  - Switching a game **to** `v1-classic` → `400 {field: physics_profile}`.
- **Packs.**
  - `POST /packs` → `201 {pack_id, pdf_url, k, kind}`. Remix packs use `k ≥ parent screens`; extend packs `k = 1`.
  - `GET /packs/{id}` → `{…, sheets: [{n, status: scanned|missing, draft_id, photo_url, scanned_at}], scanned,
    playable, complete}`. Paper builds with a pack update this checklist.
  - `GET /templates/pack/{id}.pdf` (cached).
- **Moderation.** `POST /levels/{id}/moderate` → `{safety, listed, checked}`. `checked: false` means the model is
  offline.
- **Export / import.**
  - `GET /levels/{id}/export[?version=]` and `GET /games/{id}/export` → a zip with `manifest.json`
    (`format: "dal-export", v: 1`), `levels/<id>/v<n>.json`, `library/<id>/v<n>.json`, `rules.json` and `files/…`.
  - `POST /import` (zip body or multipart `file`) → `201 {ids: {old: new}, game_id, levels, types, rejected}`.
  - Held or flagged levels are not exported (`403 publish.safety_flag`).
- **Sheet scans.**
  - `POST /scan/rules-sheet` → `{patch, asks, x_values?, x_warnings?, x_story_ink?, story?, title_suggestion?,
    game_id?, rules?}`.
  - `POST /scan/library-sheet` → `{drafts, game_id?, warnings?}`. Each draft's `name` is model-read when
    possible (`name_source: "model"`); `letter` is unique in the game.
- **Builds.** The optional `title` field is kept as the draft title.

## 3. To lane B (core, and the spec owner for CONTRACTS.md)

1. **`layout_plan` beat positions.** Please return the beat extents as an `x_*` key on the InkDoc:
   `ink.x_beats = [{section, beat, x0, x1}]`, in world cells, in plan order.
   - The deterministic fixer (§8.3 step 3) and the PLAN retry's "section 2 beat 3 needs …" sentence use it to find
     the failing beat from `report.frontier.blocking.from`.
   - Without it, D derives extents from the draft strokes' `x_beat: "<section>.<beat>"` tags (already written by
     `draw.ts`). Failing that, it estimates positions from the beat sizes (`app/mind/plan.py beat_spans`).
     `x_beats` is still preferred, because a beat with no strokes (a gap) has no extent of its own.
2. **What D sends `layout_plan`.**
   - D sends a plan already clamped by band (`PROMPT_LEVEL.clamps`) with exactly one goal at the end and every door
     after a key. Clamping again in `beats.ts` is fine.
   - D sets `ink.source = "prompt"` on the result. Please also emit it yourself, with strokes `origin: "draft"` and
     `label` roles, so perception is exact.
3. **`keyword_plan` vs the Python fallback.** D calls the core's `keyword_plan` first. `app/mind/plan.keyword_plan`
   is used only when that RPC fails, so the core's 12 canned plans stay authoritative.
4. **Record in CONTRACTS.md:**
   - The model-facing PLAN schema is flat (`mind/schemas.LevelPlanFlat`, one `FlatBeat` with sentinels). The
     19-variant `Beat` union inside `sections` is far larger than the 10-variant union the API rejected in the P0
     bakeoff. The wire form stays `LevelPlan`.
   - The export zip format and the extension keys in §2: `x_versions`, `x_title`, `x_version`, `x_error`.
   - Rules `PUT` with `apply` / `repair`, and `POST /library/{id}/update-levels`.
   - Seeded game ids: `game_world` (Starter World v2), `game_classic` (Classic Starter, the v1 ids kept), and the
     remix chain `lvl_world_l1_maya` → `lvl_world_l1_sam`.
5. **Starter dist.** `seed_v2` reads `shared/starter/dist/*.level.json` in file-name order (L1..L5).
   - It keeps each file's `id` when it is a valid id not used by another game; otherwise it uses `lvl_world_<n>`.
   - A changed `level_hash` is published as a new version on the next boot.

## 4. To lane C

D uses lane C's sheet readers and PDF makers as they now exist. Each is looked up by name in the first of
`app.cv.checkbox`, `app.cv.sheets_v2`, `app.cv.omr`, `app.cv.scan_v2` or `app.template.generate_v2` that defines
it; a missing one gives a 501 `error.not_implemented` for its route.

- **Rules sheet.** `read_rules_sheet_detail(img)` (falls back to `read_rules_sheet`).
  - `result.patch`, `result.asks` and the `x_*` keys pass through.
  - `story_jpeg` is transcribed by the new `handwriting` call (effort low, 1500 tokens, 10 s, $0.02 estimate) into
    `story` and `title_suggestion`.
  - `x_game_id`, or `game_id`, adds the resolved `rules`.
- **Library sheet.** `read_library_sheet_detail(img)` (falls back to `read_library_sheet`).
  - Each box's `name_jpeg`, when `name_has_ink`, is transcribed into `name` with `name_source: "model"`.
  - `letter` is assigned unique within the game.
  - A draft can be POSTed as-is to `/games/{id}/library`; its extra keys are ignored.
- **PDFs.** `make_rules_pdf(game_id, current=<rules>, title=<game title>)` and
  `make_library_pdf(game_id, <latest types>, title=<game title>)`.
- **Failures.** A reader exception with a `.message` MessageRef becomes a 422 with that key.

## 5. Decisions where PLAN_V2 was open

- **Classic Starter.** The plan stores migrated levels in `levels.json_v2`. D does that, and the v1 Starter World
  levels are also inserted into `levels_v2` under the v2 game `game_classic`, with their v1 ids. Without the
  `levels_v2` copy they could not appear in a v2 game; v1's own tables are unchanged.
- **Remix chain.** Sam's speedrun is a remix of Maya's Challenging level, matching v1's chain. Its timer is
  `ceil5(1.5 × fastest)` seconds, a kid `set_timer` with `x_seconds`.
- **Imports.** Imported levels are stored with `safety: "unchecked"`; held and flagged levels stay unlisted. Levels
  the bot cannot finish are stored unlisted. The only JSON changes besides ids are uploaded-file URLs.
- **Rules apply.** "Apply to all levels" saves a new version for every level of the game, not only the affected
  ones, because each level stores its own rules snapshot.
