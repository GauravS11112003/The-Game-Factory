# Draw-a-Level: One-Shot Build Plan

This plan locks every decision needed to build the hackathon version in a single pass. Nothing below needs a design conversation mid-build. Background and pitch are in [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md).

## 0. Decisions locked here (changes from the earlier chat)

| Topic | Decision | Why |
|---|---|---|
| Data store | **SQLite + local uploads folder** behind the FastAPI app. No Supabase. | One-shot buildable with zero external accounts. Postgres/Supabase is a one-file swap later (`db.py`). |
| Level look | **The rectified drawing is the backdrop.** Collision tiles are invisible. Dynamic pieces (moving platforms, enemies, doors) are cropped from the drawing. | "Your drawing IS the level" is a stronger wow than generic tiles, and it costs less art. |
| Rules input | A printed **Rules box** on the template for sentences, plus arrows/short labels inside the drawing. The vision model marks in-drawing text so it is not turned into platforms. | Handwritten text in black would otherwise become solid tiles. |
| Behavior binding | The vision model **binds behaviors to numbered components** found by CV, never to free coordinates. | Models read labels reliably; they estimate coordinates poorly. |
| Vision model | Claude via the official Python SDK, `client.messages.parse` with a Pydantic schema. | Structured output with no parsing code. Also does the kid-safety check in the same call. |
| Text-only prompt | Supplements a drawing (same interpret call, text appended). It does **not** generate geometry from nothing. | Out of scope for the hackathon. |
| Solvability check | Runs in the browser (TypeScript), before publish. | Instant overlay feedback; one implementation. |
| Start position | Default: on top of the leftmost ground cell. Writing "S" or "start" on the sheet overrides it via the vision model. | Avoids a 5th marker color. |

## 2. Constants (never change these after hour 1)

```
GRID_W = 48, GRID_H = 27, CELL = 16   → game canvas 768×432, scaled to fit the screen
Drawing area on paper: 240mm × 135mm  → one cell = 5mm × 5mm
Player body: 12×28 px (0.75 × 1.75 cells), sprite drawn at 32×48
Gravity 900 px/s², run speed 160 px/s, jump velocity −330 px/s
Variable jump: on release, if vy < −120 then vy = −120
Coyote time 80 ms, jump buffer 100 ms
Derived: max jump height ≈ 60 px (3.8 cells) → clears a 3-cell wall, not 4
         flat jump distance ≈ 117 px (7.3 cells) → clears a 6-cell gap, not 7
Bounce pad: vy = −600 (≈ 12 cells high)
Enemy/platform speeds in cells/s; default move 2, patrol 3
```

Tile codes in `grid.rows`: `0` empty, `1` solid, `2` hazard.

Conventions:
- All coordinates are **grid cells**, origin top-left, `x` right, `y` down. `bbox` is `[x0, y0, x1, y1]` inclusive.
- `components` is kept on the level so remixes can reference parent components and so the remix sheet can print their numbers.
- A cell occupied by a dynamic entity (`moving_platform`, `enemy`, `door`) is `0` in `grid.rows`; the entity owns it.
- `rules.when` vocabulary: `collect:<id>`, `touch:<id>`, `timer:<seconds>`. `rules.then`: `open:<id>`, `win`, `lose`.
- The JSON Schema in `shared/level.schema.json` encodes all of this (`additionalProperties: false` everywhere). The Python `Level` Pydantic model and the TS `types.ts` mirror it by hand; `test_compile.py` validates fixtures against the schema with `jsonschema`.

## 4. Behavior library (fixed vocabulary, v1)

| Behavior | Binds to | Params (defaults) | Compiles to | Trigger words (examples) |
|---|---|---|---|---|
| `move` | black component | `dx` (8), `dy` (0), `speed` cells/s (2) | `moving_platform` with `path: [[x,y],[x+dx,y+dy]]`, ping-pong | "moves", "slides", arrow next to a platform |
| `patrol` | red component | `dx` (6), `speed` (3) | `enemy` that walks back and forth, flips at path ends | "walks", "patrols", "moves back and forth" on spikes/monster |
| `bounce` | black component | `strength` (1.0) | `bounce_pad` on that bbox; tiles stay solid | "bouncy", "trampoline", "spring", "jump pad" |
| `key` | blue component | `opens_component_id` (required) | `key` entity (replaces that coin) + rule `collect:key → open:door` | "key", "opens the door" |
| `door` | black component | none | `door` entity; removed from grid; destroyed on `open` | "door", "gate", "wall opens" |
| `checkpoint` | any component | none | `checkpoint` entity at bbox center; respawn point | "checkpoint", "save", flag drawing |
| `timer` | level | `seconds` (required) | rule `timer:N → lose` + HUD countdown | "60 seconds", "timer", "hurry" |
| `start` | level | `component_id` or none | `player_start` at that component's bbox bottom-center | "S", "start", "begin here" |

Stretch (only if everything else is done): `gravity_flip` (zone on a blue component), `crumble` (black platform falls 0.5 s after being stood on).

Validation rules in `compile.py`: unknown behaviors are dropped; a binding whose `component_id` doesn't exist is dropped; a color mismatch is dropped; `move` on a component larger than 60 cells is dropped (it's probably the floor); a `key` without a valid `door` becomes a coin. Every drop appends a `meta.warnings` entry. **The level always compiles**, even with an empty interpretation.

## 6. CV pipeline (`vision/app/cv/pipeline.py`)

`run_scan(image_bytes, mode: "paper" | "canvas") -> CVResult`

1. **Decode + downscale** so the long edge is ≤ 2400 px. EXIF-rotate.
2. **Rectify** (`paper` only). `cv2.aruco.ArucoDetector(DICT_4X4_50)`. Need ids 0–3. If exactly 3 found, infer the 4th as the parallelogram completion. If < 3, raise `ScanError("Couldn't see the corner markers. Keep the whole sheet in frame.")`. `cv2.getPerspectiveTransform` from the 4 outer corners to the canonical 2970 × 2100 canvas; `warpPerspective`. In `canvas` mode the input *is* the drawing area; resize it to 2400 × 1350 and skip to step 5 with ideal swatch colors.
3. **Calibrate.** For each swatch, take the median Lab of the eroded patch. Add a "paper" class sampled from the empty swatch plus the margins of the drawing area. That gives 6 class centers: black, red, green, blue, gray, paper.
4. **Classify** every pixel of the drawing area by nearest Lab center (vectorized NumPy, `argmin` over 6 distances). `gray` and `paper` → background. Apply a confidence margin: if the nearest and second-nearest distances are within 8 Lab units and one of them is background, choose background (kills shadows).
5. **Clean** each color mask: `morphologyEx OPEN 3×3` (specks), `CLOSE 5×5` (join strokes), then dilate by `cell/4` for the coverage step only (thin marker lines still register).
6. **Components.** `connectedComponentsWithStats` per color (8-connectivity). Drop area < 0.3 cell. Number them 1..N in reading order (top-left first). Record `{id, color, bbox_cells, area_cells, mask}`.
7. **Grid.** Coverage per cell per color (`cv2.resize` with `INTER_AREA` from the dilated mask to 48 × 27 gives the fraction directly). `solid` if black ≥ 0.25, `hazard` if red ≥ 0.25 (hazard wins over solid in the same cell).
8. **Point entities.** Largest green component → `goal` at its centroid cell (no green → warning + goal at the top of the rightmost ground column). Each blue component → `coin` at its centroid cell. `player_start` default: top of the leftmost solid column, clamped so the 2-tall body fits.
9. **Sprite.** Crop the character box; "ink" = not paper class; keep the largest connected blob plus anything within 5 px; alpha = ink mask blurred 1 px; tight-crop; resize to fit 32 × 48 with `INTER_NEAREST` (doodle look); save `player.png`. No ink → `sprites.player = null` (engine uses the default doodle).
10. **Backdrop.** Drawing area with all background-class pixels set to pure white, resized to 768 × 432, saved `backdrop.png`.
11. **Annotated image for the model.** The rectified full sheet at 1500 px wide with each component's id drawn in magenta (a color not in the palette) at its bbox top-left, plus a 1-cell coordinate ruler on the axes. Saved `annotated.jpg`.
12. **QR.** `cv2.QRCodeDetector().detectAndDecode` on the rectified sheet's QR region. Parse `dal1|...`. Failure → `parent_hint = null` (the UI asks).
13. **Debug** mode writes every intermediate image to a folder; the API returns their URLs under `debug` when `?debug=1`.

Output `CVResult`: `{grid_rows, components, goal, coins, player_start, sprite_path, backdrop_path, annotated_path, qr_payload, warnings}`.

## 7. Vision-model interpretation (`vision/app/llm/`)

One call per scan. Python SDK, structured output, image + text.

```python
class Binding(BaseModel):
    component_id: int
    behavior: Literal["move","patrol","bounce","key","door","checkpoint","start"]
    params: dict[str, float | int]  # validated per behavior in compile.py

class Interpretation(BaseModel):
    title: str | None
    annotation_component_ids: list[int]   # text, arrows, labels: not geometry
    bindings: list[Binding]
    timer_seconds: int | None
    notes_transcript: str                 # everything handwritten, verbatim
    safety_ok: bool
    safety_reason: str | None

response = client.messages.parse(
    model="claude-opus-5",
    max_tokens=4000,
    system=SYSTEM_PROMPT,
    messages=[{"role": "user", "content": [
        {"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": annotated_b64}},
        {"type": "text", "text": build_user_message(components, parent_components, extra_prompt)},
    ]}],
    output_format=Interpretation,
)
if response.stop_reason == "refusal": return None
return response.parsed_output
```

System prompt contents (keep it under one page):
- What the sheet is, what the magenta numbers mean, that geometry is already extracted.
- The behavior table from §4, with parameter ranges (`dx` 2–20, `speed` 1–6, `strength` 0.5–2, `timer` 10–300) and color constraints.
- "Bind only to listed component ids. If an arrow sits next to a platform, the arrow is an annotation and the platform gets `move` in the arrow's direction, `dx` ≈ the arrow's length in cells."
- "Anything written with letters is an annotation component."
- "If nothing is written, return empty bindings. Never invent mechanics that aren't on the sheet."
- Safety: flag drawings or words that are sexual, hateful, or graphically violent; coins/spikes/monsters are fine.

User message: JSON list of components (`id, color, bbox, area_cells`), the parent's components if remixing (prefixed so ids don't collide: parent components keep their ids; new ones continue the sequence), and the optional typed prompt from the canvas/prompt path.

Fallbacks, in order: `DAL_FAKE_LLM=1` → read `shared/fixtures/interpretations/<sha1-of-image>.json` or `default.json`. API error, timeout (20 s), or refusal → `None` → the level compiles with CV only and `meta.warnings` gets `"rules_not_read"`. The demo never blocks on the model.

## 8. Compile (`vision/app/compile.py`)

`compile_level(cv: CVResult, interp: Interpretation | None, parent: Level | None, author, game_id) -> Level`

1. Start from the parent's `grid.rows`, `components`, `entities` if remixing; otherwise empty. New components get ids after the parent's max.
2. Remove annotation components: clear their cells from the grid (only cells where that component supplied the coverage).
3. For each valid binding (rules in §4):
   - `move` / `door`: clear the component's cells from the grid; crop its pixels from the backdrop into `comp_<id>.png` (RGBA, white → transparent) and whiten them in the backdrop; create the entity.
   - `patrol`: same, on a red component; hazard cells cleared.
   - `bounce`: keep tiles; add `bounce_pad` with the bbox.
   - `key`: replace the coin at that component with a `key` entity; add rule `collect:<key> → open:<door>`.
   - `checkpoint`, `start`: point entities at bbox bottom-center.
   - `timer`: rule `timer:N → lose`.
4. Add `goal`, remaining `coins`, `player_start` (binding override → else CV default).
5. Fill `meta.notes_transcript`, `meta.warnings`, `title` (interp → else "Untitled level").
6. Validate with the `Level` model. Write the draft to `uploads/drafts/<draft_id>/` and return it.

## 10. Web app

Vanilla TS + Phaser 3, hash routes. Mobile-first, landscape game.

- `#/` **Home**: feed cards (backdrop thumbnail, title, author, level count, likes). Buttons: **Play**, **Scan a sheet**, **Draw on screen**, **Print blank sheet**.
- `#/scan?parent=&game=` **Scan**: `<input type="file" accept="image/*" capture="environment">` (opens the phone camera with no HTTPS requirement). Upload with a progress state ("Reading your drawing… / Reading your rules…"). Then **Preview**: backdrop with the grid overlay toggle, entity markers, solver overlay (green tint on reachable standing cells; goal pulses red if unreachable, with the message "Goal can't be reached. Green shows where the player can get to."). Buttons: **Play test** (plays the draft), **Publish** (name field → `POST /api/levels`), **Retake**. If `parent_hint` is null but the user came from a remix link, pass `parent_id` explicitly.
- `#/draw` **Canvas**: 768 × 432 canvas, brushes in the 4 palette colors (8 px round), eraser, undo; a 128 × 128 character canvas; a rules textarea. Submit composes a PNG of the drawing area and posts `mode=canvas` with `prompt` = rules text. (The canvas path also serves as the lighting-proof demo fallback.)
- `#/play/:levelId` and `#/play/draft/:draftId` **Play**: Phaser `LevelScene`. HUD: coins, timer, deaths, restart. On goal: overlay with **Next level** (if the game has one), **Remix this**, **Home**. Keyboard: arrows/WASD + space. Touch: left/right/jump buttons in `touch.ts` (shown when `pointer: coarse`).
- `#/remix/:levelId` **Remix**: "Print this sheet, draw your additions in color, then scan it." Link to the remix PDF, button **Scan now** (→ `#/scan?parent=<id>`), button **Remix on screen** (→ `#/draw?parent=<id>`, which loads the parent backdrop in gray under the canvas).
- `#/tree/:levelId` **Tree**: nested list rendered as an indented tree with connector lines (CSS), each node showing thumbnail, title, author, and a Play link. Good enough; no graph library.

Engine details (`web/src/game/`):
- `LevelScene.create(level)`: add backdrop image at (0,0) 768×432; build a blank tilemap 48×27×16 with a runtime-generated 3-tile tileset (`Graphics.generateTexture`): tile 1 invisible-solid (alpha 0; alpha 0.3 when debug is on), tile 2 hazard (invisible; collision callback = die). `layer.setCollision([1])`, `setTileIndexCallback(2, die)`.
- `Player`: texture from `sprites.player` or `assets/default_player.png`; arcade body 12×28 offset to the sprite's feet; constants from `constants.ts`; coyote/buffer/variable jump implemented in `update`.
- Behaviors are small classes constructed from entities, each with `create(scene)` and `update(dt)`. `MovingPlatform`: kinematic image (`comp_<id>.png`) tweened ping-pong between path points; player rides it by inheriting `platform.body.deltaX()` when `touching.down`. `Patroller`: image with velocity ±speed, flips at path ends or when `blocked.left/right`; overlap = die. `BouncePad`: zone over the bbox; on overlap from above set `vy = −600`. `KeyDoor`: key sprite overlap → `rules.emit("collect:e8")`; door is a static image with a static body; `open:e9` destroys it with a puff. `Checkpoint`: overlap sets respawn. `Timer`: countdown in the HUD, emits `timer:N`.
- `rules.ts`: `on(when, fn)`, `emit(event)`; `then` actions `open:`, `win`, `lose`. The scene registers each level rule once.
- Death: respawn at the last checkpoint after a 300 ms shake. Win: `goal` overlap.

## 11. Solvability (`web/src/solver/solve.ts`)

Discrete simulation using the engine's constants, in pixel space, 60 Hz, AABB vs the grid.
- Nodes = **standing positions**: a cell `(x,y)` where the player's feet can rest (cells `(x,y+1)` solid or a bounce pad/moving-platform path cell, `(x,y)` and `(x,y−1)` empty and not hazard).
- From each node, try the action set: walk L/R for 1 cell; jump with hold time ∈ {0.1 s, 0.2 s, full} × direction ∈ {L, none, R}; drop off an edge L/R. Simulate until the body lands on something standable, dies (hazard, bottom of the grid), or 3 s pass. Landing cell → edge.
- Approximations (documented in code): moving platforms are standable along their whole path; doors are passable; enemies ignored; bounce pads add a "jump with vy = −600" action.
- BFS from `player_start`. Result: `{solvable, reachable: Set<cellKey>, reason?}`. Fixture tests: `flat.json` solvable, `too_wide_gap.json` and `too_tall_wall.json` unsolvable, `key_door.json` solvable.
- Runs in < 50 ms for 48 × 27; no worker needed.

## 16. Tests (what "one shot" relies on)

- `make_synthetic.py`: renders the template PNG, draws a known level in the four palette colors with Pillow (thick lines), writes handwritten-looking labels, applies a random perspective warp, gamma 0.7–1.4, slight blur, JPEG 80 → `shared/fixtures/photos/synth_<n>.jpg` plus the expected grid. Tests assert rectification error < 3 px at the corners, grid IoU ≥ 0.9, coin count exact, goal within 1 cell, sprite non-empty.
- `test_compile.py`: fixture CVResult + fixture Interpretation → level validates against the schema; annotation cells removed; invalid bindings dropped with warnings; remix compose keeps parent entities.
- `solve.test.ts`: the four fixture levels.
- Manual checklist (`docs/checklist.md`): real sheet under 3 lighting conditions, a sheet with a thin pen (expect warning, still plays), a sheet with no goal, an impossible level, a remix.

## 17. Risks and the built-in answers

| Risk | Mitigation already in the plan |
|---|---|
| Venue lighting | Swatch calibration per photo; clip lamp; backup real photos; canvas path as a camera-free fallback |
| Thin or faint ink | Dilation before coverage; template says "thick markers"; warning when median stroke width < 3 px |
| Model latency or refusal | 20 s timeout → CV-only level with a warning; fake mode for rehearsal; UI shows "Reading your rules…" |
| Text becoming platforms | Rules box outside the drawing area; model flags in-drawing text; a fallback heuristic drops black components under 4 cells with no neighbors within 1 cell |
| Impossible kid levels | Solver overlay before publish; the level still publishes if they insist (`solvable: false` badge) |
| Phone can't reach the laptop | LAN first, tunnel second, laptop webcam third (`scan.ts` also accepts a desktop file) |
| Scope creep | §4 is the whole behavior list; §13 phases 8–9 are the only polish; stretch items are named and last |

## 18. Explicitly out of scope

Accounts and auth, comments, search, level generation from a text prompt alone, non-platformer genres, custom tile art, sound beyond two SFX (jump, coin), multiplayer, GitHub mirroring (mention it on a slide as the roadmap).

## 19. Definition of done

A judge, with no instructions beyond the sheet's legend, draws on a printed remix sheet, writes one rule, scans it with the team's phone, and plays their level with their own doodle as the character within 15 seconds. The tree page shows their level under the original with their name. The whole thing runs on one laptop and one phone with no external service except the Claude API, and still runs (minus handwritten rules) with the network cable pulled.
